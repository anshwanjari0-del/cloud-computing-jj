Fundamentals Module 01

What is Cloud Computing?

Definition

Cloud computing is the on-demand delivery of computing services—including servers, storage, databases, networking, software, and analytics—over the internet ("the cloud") with pay-as-you-go pricing, eliminating the need to own and maintain physical data centers.

Practical Example

Instead of purchasing physical servers and renting air-conditioned colocation rack space to run a new mobile application, a startup launches two virtual servers on AWS or Azure in five minutes, paying only for the exact compute minutes their users consume.

Key Concepts
  • On-Demand Self-Service: Instant resource provisioning without manual vendor intervention.
  • Broad Network Access: Capabilities accessible across standard internet protocols on any client device.
  • Resource Pooling: Provider compute resources pooled to serve multi-tenant customers dynamically.
Summary

Cloud computing shifts computing from a fixed physical asset to a flexible utility, granting individuals and global enterprises alike instant access to enterprise-grade infrastructure.

Deep Dive: The Utility Computing Paradigm

Just as modern households plug appliances into the electrical grid without building their own power generators, modern software teams consume compute and storage through standardized APIs without maintaining physical diesel backups, cooling chillers, or fiber-optic patches.

Reference Standard: National Institute of Standards and Technology (NIST SP 800-145).
Fundamentals Module 02

History & Evolution of Cloud

Definition

The evolution of computing from massive centralized mainframes with time-sharing in the 1960s, through client-server architectures, grid computing, and hardware virtualization in the late 1990s, culminating in modern on-demand public cloud platforms in the mid-2000s.

Practical Example

In 1999, Salesforce pioneered delivering business software purely via browser (SaaS). In 2006, Amazon launched AWS with Simple Storage Service (S3) and Elastic Compute Cloud (EC2), allowing developers to programmatically rent raw server compute via REST APIs for pennies per hour.

Key Concepts
  • Mainframes & Time-Sharing (1960s): John McCarthy envisioned computation organized as a public utility.
  • Virtualization Breakthrough (late 1990s): VMware and Xen enabled multiple operating systems on one server.
  • Commercial Public Hyperscalers (2006–Present): AWS launch (2006), Google App Engine (2008), Microsoft Azure (2010).
Summary

Cloud computing is not a sudden accident, but a six-decade technological convergence of time-sharing, high-speed broadband, hardware virtualization, and automation.

Deep Dive: The Shift from Bare-Metal to Cloud-Native

Prior to cloud computing, launching a software product required forecasting capacity 6-12 months in advance, placing hardware purchase orders, racking machines, and paying high capital expenses. Today, infrastructure is defined purely as software code (Infrastructure as Code).

Fundamentals Module 03

Characteristics & Benefits of Cloud

Definition

The NIST specification defines five essential characteristics of cloud computing (on-demand self-service, broad network access, resource pooling, rapid elasticity, and measured service) that deliver tangible business benefits like agility, reliability, and cost-efficiency.

Practical Example

An e-commerce website experiences a 10x traffic spike on Black Friday. Thanks to rapid elasticity and measured service, auto-scaling automatically spins up 20 additional server instances for six hours and terminates them afterwards, paying only for those exact active hours.

Key Concepts
  • Rapid Elasticity: Capabilities can be elastically provisioned and released to scale out and in.
  • Measured Service: Resource usage is monitored, controlled, and reported transparently.
  • Global Reliability: Multi-region replication safeguards uptime against localized natural disasters.
Summary

The NIST characteristics distinguish genuine cloud computing from traditional shared hosting by guaranteeing elasticity, automated measurement, and on-demand provisioning.

Deep Dive: The 5 Essential NIST Characteristics

If a system requires an email ticket or human approval to allocate a virtual server, or charges a flat monthly fee regardless of actual consumption, it does not fully meet the strict NIST cloud definition.

Deployment Models Module 04

Public, Private, Hybrid & Community Cloud

Definition

Cloud deployment models categorize where infrastructure is physically hosted and who has exclusive access to it: open public hyperscalers, dedicated private infrastructure, connected hybrid setups, or shared community consortia.

Practical Example

A commercial healthcare network stores sensitive patient health records on a HIPAA-compliant private cloud within their own data center, while hosting their public patient education portal on a public cloud like AWS to leverage global content delivery networks.

Key Concepts
  • Public Cloud: Multi-tenant infrastructure owned by third-party providers (AWS, Azure, GCP).
  • Private Cloud: Single-tenant infrastructure exclusively operated for one organization.
  • Hybrid Cloud: Seamless orchestration between private on-premises and public cloud resources.
  • Community Cloud: Shared infrastructure among organizations with common mission or regulatory standards.
Summary

Selecting the proper deployment model hinges on regulatory compliance, data residency laws, legacy hardware investments, and performance requirements.

Deep Dive: Direct Cloud Interconnects

Hybrid cloud architectures frequently rely on dedicated private fiber circuits (such as AWS Direct Connect or Azure ExpressRoute) rather than public internet tunnels to achieve sub-millisecond latencies and high throughput between enterprise data centers and the cloud.

Service Models Module 05

IaaS, PaaS, and SaaS (Service Models)

Definition

The three primary cloud service delivery layers representing varying levels of abstraction: Infrastructure as a Service (raw compute/network), Platform as a Service (managed application runtimes), and Software as a Service (end-user ready applications).

Practical Example

IaaS: You rent an Amazon EC2 instance and configure Ubuntu OS, Nginx, and Python yourself.
PaaS: You push code to Google App Engine or AWS Elastic Beanstalk; the cloud configures the runtime automatically.
SaaS: You log in to Google Workspace or Dropbox to work directly without writing any code.

Key Concepts
  • IaaS (Infrastructure as a Service): Maximum control over OS, kernel parameters, and networking.
  • PaaS (Platform as a Service): Focus solely on code; cloud provider manages OS patches and scaling.
  • SaaS (Software as a Service): Turnkey cloud software consumed via web browsers and mobile apps.
  • Shared Responsibility Model: Customer responsibilities decrease as you move from IaaS to PaaS to SaaS.
Summary

Choose IaaS for complete operational control, PaaS for accelerated developer productivity, and SaaS for ready-to-use business software.

Deep Dive: The Shared Responsibility Division

In IaaS, the customer must apply security patches to the guest operating system. In PaaS, the provider patches the OS and language runtime. In SaaS, the provider manages the entire application, leaving only data access management to the customer.

Architecture Module 06

Virtualization & Containers

Definition

Virtualization is the abstraction of physical hardware using hypervisors to create multiple isolated Virtual Machines (VMs). Containerization takes abstraction further by isolating processes at the operating system level, sharing a single host kernel for ultra-fast, lightweight deployments.

Practical Example

A Virtual Machine takes 60 seconds to boot a full Windows Server guest OS (taking 20 GB of disk space). In contrast, a Docker container running a microservice starts in 200 milliseconds, packages only application binaries and dependencies, and consumes just 150 MB.

Key Concepts
  • Type-1 (Bare-Metal) Hypervisors: Run directly on physical server hardware (e.g. VMware ESXi, KVM).
  • Containers (OCI / Docker): Package code + libraries while sharing the host OS kernel via Linux namespaces & cgroups.
  • Container Orchestration: Kubernetes (K8s) automates deployment, scaling, and self-healing across container clusters.
Summary

Virtual Machines provide strong hardware isolation for legacy and multi-OS workloads, while containers provide rapid portability and density for cloud-native microservices.

Deep Dive: Modern Firecracker & MicroVMs

Modern cloud providers combine the security isolation of VMs with the sub-second boot speed of containers using lightweight microVM technologies like AWS Firecracker, powering serverless runtimes like AWS Lambda and Fargate.

Storage & Data Module 07

Cloud Storage & Managed Databases

Definition

Cloud storage encompasses specialized tiers for data persistence—Object, Block, and File storage—paired with fully managed relational (SQL) and non-relational (NoSQL) database engines featuring automated backups, clustering, and scaling.

Practical Example

A video streaming platform stores terabytes of raw MP4 video files in AWS S3 or Google Cloud Storage (Object Storage), mounts an NVMe SSD volume (Block Storage) to its encoding servers for scratch performance, and queries subscriber profiles in Amazon DynamoDB (NoSQL).

Key Concepts
  • Object Storage: Flat address space accessed via HTTP REST APIs (AWS S3, Azure Blob). 99.999999999% durability.
  • Block Storage: High-performance virtual disks attached to individual VMs (AWS EBS, Azure Managed Disk).
  • File Storage: Shared network filesystem accessible simultaneously by multiple servers (NFS/SMB, AWS EFS).
  • Relational vs NoSQL: ACID-compliant SQL (RDS, Cloud SQL) vs horizontally scalable key-value/document stores (DynamoDB, Cosmos DB).
Summary

Match storage types to application I/O patterns: Object storage for static media and data lakes, Block storage for OS drives, and Managed databases for transaction processing.

Deep Dive: The 11 Nines of Durability

Cloud object storage systems like S3 automatically replicate data across at least three geographically separated availability zones within a region, yielding an engineered annual durability of 99.999999999% (if you store 10,000,000 objects, you would expect to lose one every 10,000 years).

Networking Module 08

Cloud Networking & VPC Architecture

Definition

Software-Defined Networking (SDN) in the cloud enables users to construct isolated virtual networks (VPC or VNet), define private Classless Inter-Domain Routing (CIDR) blocks, route internet traffic via gateways, and balance global user requests using CDNs.

Practical Example

A bank places its web load balancer in a public subnet with an Internet Gateway, but strictly places its payment database in an isolated private subnet with no public IP, reachable only by internal application servers via strict Security Group rules.

Key Concepts
  • Virtual Private Cloud (VPC): Logically partitioned private virtual network in your cloud tenant.
  • Public vs Private Subnets: Public subnets route directly to an Internet Gateway; private subnets use NAT for egress only.
  • Security Groups & NACLs: Stateful virtual firewalls at the instance level vs stateless filters at the subnet level.
  • Content Delivery Network (CDN): Globally distributed edge points of presence caching static assets close to end users.
Summary

VPC architecture forms the perimeter and backbone of cloud security. Isolating workloads into segmented subnets protects internal databases from direct public exposure.

Deep Dive: CIDR Block Sizing

Standard cloud VPCs typically use private RFC 1918 address space, such as 10.0.0.0/16 (providing 65,536 IP addresses). Subnets are typically divided into /24 blocks (256 addresses each), spanning distinct Availability Zones for redundancy.

Security Module 09

Security, Identity & Access Management (IAM)

Definition

The foundational framework and policies ensuring that authorized identities (human operators and software services) have precisely the granular access permissions necessary to perform their duties, rooted in Zero Trust and Least Privilege principles.

Practical Example

Rather than embedding permanent AWS secret keys into web server code, developers assign an IAM Role to the virtual machine. The cloud provider automatically injects short-lived, rotatable temporary security tokens with permissions restricted strictly to reading from one specific S3 bucket.

Key Concepts
  • Principle of Least Privilege (PoLP): Granting only the bare minimum permissions required for a role.
  • Multi-Factor Authentication (MFA): Mandatory second-factor verification protecting root and privileged user accounts.
  • Encryption at Rest & in Transit: Encrypting stored databases via KMS (AES-256) and TLS 1.3 for in-flight requests.
  • Audit Logging: Immutable API tracking (AWS CloudTrail, Azure Activity Log) recording who made every API call.
Summary

In cloud computing, identity is the new security perimeter. Strict IAM policies combined with continuous audit logging prevent unauthorized privilege escalation and data exfiltration.

Deep Dive: Never Use Root Credentials for Daily Work

Every major cloud provider strongly advises locking away account root credentials behind a physical hardware MFA key immediately upon creation, conducting all administrative tasks via federated Single Sign-On (SSO) roles.

Architecture Module 10

Scalability, Elasticity & High Availability

Definition

The architectural capability of a system to handle increased load by adjusting resources (scalability), dynamically adapt to changing demand in real-time (elasticity), and remain fully operational without interruption despite hardware or facility failures (high availability).

Practical Example

A news website distributes its application servers across three separate Availability Zones behind an Application Load Balancer. If a lightning strike knocks out one entire data center facility, health checks automatically divert 100% of traffic to surviving zones without dropping a single visitor request.

Key Concepts
  • Vertical Scaling (Scale-Up): Adding more CPU/RAM to an existing instance (has physical hardware ceilings).
  • Horizontal Scaling (Scale-Out): Adding more identical stateless instances in parallel (virtually unlimited).
  • Elastic Auto-Scaling: Target-tracking policies that automatically spin instances up and down on CPU/request metrics.
  • High Availability (HA): Achieving 99.99% ("four nines") uptime through redundant, geographically separated nodes.
Summary

Design for failure: build stateless application tiers that scale horizontally across multiple availability zones to withstand component breakdowns gracefully.

Deep Dive: RPO and RTO in Disaster Recovery

High availability architectures are guided by two fundamental metrics: Recovery Point Objective (RPO) (the maximum acceptable data loss in minutes/hours) and Recovery Time Objective (RTO) (the maximum acceptable downtime duration).

Modern Cloud Module 11

Serverless Computing & FaaS

Definition

An execution model where the cloud provider dynamically manages the allocation, provisioning, and scaling of servers. Code runs in stateless compute containers triggered by events, and organizations pay zero dollars when no code is actively executing.

Practical Example

Whenever a user uploads an avatar image to an S3 bucket, an event triggers an AWS Lambda function. The function resizes the picture to thumbnail dimensions in 45 milliseconds and saves it. The cost for processing 10,000 images is less than two cents.

Key Concepts
  • Function as a Service (FaaS): Ephemeral micro-functions (AWS Lambda, Azure Functions, Google Cloud Functions).
  • Event-Driven Triggers: HTTP requests via API Gateway, database mutations, message queues, or scheduled cron timers.
  • Zero Idle Billing: You never pay for server idle time; billing is metered in 1ms runtime increments.
  • Cold Starts: Initial latency penalty when a function container is initialized from an idle state.
Summary

Serverless does not mean there are no servers; it means developers are completely freed from server maintenance, focusing 100% on business application logic.

Deep Dive: Serverless Containers (Cloud Run & Fargate)

Serverless has expanded beyond single code snippets into entire container workloads. Services like Google Cloud Run and AWS Fargate allow developers to run standard Docker containers serverlessly, automatically scaling to zero when traffic stops.

Operations & FinOps Module 12

Cloud Cost Management & FinOps

Definition

The operational discipline, architectural practices, and cultural framework (Financial Operations or FinOps) that enable organizations to maximize business value from cloud investments through visibility, rightsizing, commitment discounts, and real-time cost governance.

Practical Example

By auditing their cloud bill, a development team discovers five idle database instances running over weekends. They configure automated shutdown schedules for staging environments and purchase a 1-year Savings Plan for steady production workloads, cutting their monthly bill by 42%.

Key Concepts
  • Pricing Models: On-Demand (pay-per-second, flexible), Reserved / Savings Plans (up to 72% discount for 1-3 yr commitments), and Spot Instances (up to 90% discount for fault-tolerant batch work).
  • Mandatory Cost Allocation Tagging: Labeling every resource with Environment, Owner, and CostCenter.
  • Rightsizing: Downsizing over-provisioned virtual machine sizes based on observed average CPU and memory utilization.
  • Automated Budget Alerts: Setting anomaly detection alarms to immediately trigger when projected spending exceeds monthly thresholds.
Summary

Unmanaged cloud computing can rapidly lead to surprise bills. Adopting FinOps best practices ensures technical agility without sacrificing financial discipline.

Deep Dive: The 3 Phases of FinOps

The FinOps Foundation defines three continuous phases: Inform (visibility and allocation through tagging), Optimize (rate optimization via commitments and usage rightsizing), and Operate (continuous governance, automated policies, and engineering KPIs).
